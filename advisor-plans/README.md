## Dependency notes

- Plans 001–003 close correctness/privacy risks before configuration cleanup.
- Plan 005 depends on the telemetry characterization in Plan 004 so latency changes are measurable.
- Plan 007 uses the seams created by Plan 006 and must never use production credentials.
- Plans 010–011 are refactors; they require the P1 fixes and their regression tests first.
- Plan 016 is a design/deprecation spike, not permission to remove flags blindly.
- Plan 017 supersedes the remediation trigger recorded in Plan 012. It must
  complete before a production dependency refresh or the next voice-stack
  release.

## Findings considered and rejected

- Caller-supplied `X-Forwarded-For` was not planned as a vulnerability: the runtime binds the API
  to loopback and the deployment documents a single trusted proxy boundary.
- TTS/cache and rejoin “unbounded growth” findings were rejected because eviction and bounded
  batches are present in the current Rust implementation.
- Existing `plans/` entries are legacy TypeScript plans and are not duplicated here.
- Plan 012's historical inventory is not a remediation: the 2026-08-19 audit
  found advisory-bearing production dependency paths, which are tracked in
  Plan 017.
